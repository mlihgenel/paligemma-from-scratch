# The SigLIP encoder

<p className="lead">27 identical layers, each with two blocks: first the patches look at each other (attention), then each patch is transformed on its own (MLP). The shape is <S s="1, 256, 1152" ax="B,T,D" /> from start to end. What changes is what each token knows.</p>

## Attention, tensor by tensor

Following the tensor shapes is enough to understand multi-head attention. Below is a small example with 4 tokens, 6 dims and 2 heads. Every cube is a real number (random weights, computed in JS). The real model has 256 tokens, 1152 dims and 16 heads.

<Scrolly label="SiglipAttention.forward" figure={(s) => <AttentionScene step={s} />}>
<Step>**Input** <S s="T, D" ax="T,D" /> (batch omitted). Patch vectors after the LayerNorm.</Step>
<Step>**`q_proj`, `k_proj`, `v_proj`**: three separate Linears (with bias), each <S s="T, D" ax="T,D" /> → <S s="T, D" ax="T,D" />. q is "what am I looking for", k "what do I have", v "what I give if I am found".</Step>
<Step>**`view(B, T, H, hd).transpose(1, 2)`**: D is split as H × hd and the head axis moves forward: <S s="H, T, hd" ax="H,T,hd" />. No number changed in memory. Each head now has its own small T × hd matrix.</Step>
<Step>**`q @ k.transpose(-2, -1) * scale`**: a <S s="T, T" ax="T,T" /> score matrix per head. Cell (i, j): how well token i "matches" token j. Dividing by √hd keeps the size of the scores independent of the dimension.</Step>
<Step>**`softmax(dim=-1)`**: every row becomes a probability distribution that sums to 1. No mask: every patch can see every patch (unlike Gemma's causal mask).</Step>
<Step>**`wei @ v_states`**: each token takes a weighted average of the v's: <S s="H, T, hd" ax="H,T,hd" />. This is where information moves between tokens.</Step>
<Step>**`transpose(1, 2).contiguous().reshape(B, T, C)`**: the heads side by side again: <S s="T, D" ax="T,D" />. `contiguous()` is needed because after the transpose the memory layout is no longer in order, and `view` does not accept that.</Step>
<Step>**`out_proj`**: the final Linear that mixes what the heads found. The output has the same shape as the input: ready to be added to the residual.</Step>
</Scrolly>

## Concept questions

<ConceptQ n={1} q="What is the difference between pre-norm (LN before the residual) and post-norm? Which one does SigLIP use? Why is there an extra post_layernorm at the end?">
Post-norm: <span className="mono">x = LN(x + f(x))</span>. Pre-norm: <span className="mono">x = x + f(LN(x))</span>. SigLIP (and Gemma) use pre-norm: the stream itself is never normalized and the identity path stays unbroken. That protects the gradient in deep models (<Link to="/gemma/residual">4.2</Link>). The price: the last layer outputs an unnormalized, grown stream (the chart above). <code>post_layernorm</code> normalizes it in one go.
</ConceptQ>
<ConceptQ n={2} q="Why is there no attention mask here? Why would the causal tril mask of a language model not fit?">
<code>tril</code> (the causal mask) hides the future in a language model: while producing a token it must not see the ones after it. An image has no "future". All 256 patches exist at once, and a patch's meaning depends on its neighbors in every direction (the top and bottom of a letter). With a causal mask the top-left patch could never see the bottom-right one.
</ConceptQ>
<ConceptQ n={3} q="27 layers × 16 heads: how many parameters of so400m are in attention, and how many in the MLP?">
Attention per layer: 4 × 1152² + 4 × 1152 ≈ 5.31 M. MLP: 2 × 1152 × 4304 + 4304 + 1152 ≈ 9.92 M. Over 27 layers, attention ≈ 143 M and MLP ≈ 268 M. The head count does not change the parameters, it only decides how the same D is split. The bars above are measured from the project's model.
</ConceptQ>
