# GemmaAttention

<p className="lead">The only place where tokens see each other. Each token compares its query with all the keys and mixes the values with the resulting scores. The pieces from the previous two pages (<Link to="/gemma/rope">RoPE</Link> and <Link to="/gemma/mqa">repeat_kv</Link>) come together here.</p>

## At a glance

In one layer, attention follows this path: projection, splitting into heads, RoPE, expanding K/V, scores, mask, softmax, mixing with the values, merging the heads, output projection. The code first sets up the parameters of this path (`__init__`), then walks it (`forward`).

<Scrolly label="GemmaAttention.forward" figure={(s) => <AttnFlow step={s} />}>
<Step>**Inputs.** The normalized copy of the stream <S s="B, T, D" />, the RoPE table (cos, sin) and the mask. The output will have the same shape as the input: attention writes an **update** to the stream.</Step>
<Step>**Projections.** Q, K and V go through separate <code>Linear</code>s. Then the last axis is split into heads and the head axis moves forward: the heads now act like an independent batch.</Step>
<Step>**RoPE.** Only Q and K are rotated. The shapes do not change; the values rotate by position.</Step>
<Step>**repeat_kv.** The single KV head is expanded to the 8 Q heads. This is only for the shape requirement of the matmul.</Step>
<Step>**Scores.** <code>q @ kᵀ</code>: one number per token pair in every head. Scaled by 1/√256 = 1/16.</Step>
<Step>**Mask.** A very small number is added where a token must not look.</Step>
<Step>**Softmax.** Per row. The blocked positions get weight 0, and every row sums to 1. In <code>float32</code>.</Step>
<Step>**Mix with the values.** Each token takes a weighted average of the V's of the tokens it looks at.</Step>
<Step>**Merge the heads and project out.** 8 heads × 256 = 2048, then <code>o_proj</code>. The same shape as the layer input.</Step>
</Scrolly>

## Why 1/√head_dim?

The dot product of two random <code>head_dim</code>-dimensional vectors has a standard deviation of <code>√head_dim</code>. With <code>head_dim = 256</code> the scores spread around ±16. Softmax is exponential, so with that spread one token takes almost all the weight: attention turns into a "hard choice", and the gradient dies. 1/√head_dim keeps the spread at 1, independent of head_dim.

## The mask: who may see whom?

In a causal language model a token may only see <b>itself and the tokens before it</b>; otherwise it would see the answer during training. That means blocking the half of the score table above the diagonal. The blocked positions are closed with an **additive mask**: allowed positions 0, blocked positions the smallest number. In softmax, <span className="mono">exp(−very large) = 0</span>.

<CodeWalk file="gemma.py" symbol="make_causal_mask" notes={[
  { match: "mask = torch.full((T, past_len + T), torch.finfo(dtype).min", title: "fill with the smallest number", text: <><code>finfo.min</code> instead of -inf. A fully blocked row gives NaN in softmax with -inf, and equal weights with <code>finfo.min</code>. A causal mask never has a fully blocked row, but PaliGemma's masks and padding can.</> },
  { match: "mask = torch.triu(mask, diagonal=past_len + 1)", title: "above the diagonal", text: <><code>triu(diagonal=1)</code> keeps what is <b>above</b> the diagonal and sets the rest to 0: <code>j &gt; i</code> is blocked, <code>j ≤ i</code> allowed. <code>past_len</code> is for the KV cache (0 by default, which gives the usual square mask).</> },
  { match: "return mask[None, None]", title: "broadcasting", text: <><S s="1, 1, T, T" ax="B,H,T,T" />: broadcast over the batch and head axes, so every batch and head sees the same mask.</> },

<Predict q="Can a row entering softmax be fully blocked under a causal mask?" hint="Which tokens can token i see?">
<b>No</b>: the diagonal is allowed (<span className="mono">j = i</span>), so every token sees at least itself. The mask still uses <code>finfo.min</code> instead of <code>-inf</code>, because PaliGemma's masks and padding can produce fully blocked rows, and <code>-inf</code> would produce NaN there.
</Predict>
