## ModuleList, list, Sequential

<Fig wide caption={<><b>Three containers, two Linear layers.</b> The same experiment as with the project's module: a plain Python list does <b>not register</b> the parameters. <code>model.parameters()</code> does not see them, the optimizer does not update them, <code>load_state_dict</code> does not load them, <code>.to(device)</code> does not move them. Without any error.</>}>
<Containers />
</Fig>

<Callout kind="dikkat" title="A silent bug">
A model written with a plain list runs and produces the right shapes. But <code>load_state_dict</code> rejects the weights of all 18 layers as "unexpected keys" (an error with strict=True, silently skipped otherwise). The layers stay at their random initial weights. That is why the first thing <code>check_gemma.py</code> does is compare the key sets.
</Callout>

`nn.Sequential` registers the parameters, but it chains `forward` as `x → layer1(x) → layer2(...)` with **a single argument**. Attention needs the cos/sin table and the mask passed to every layer too, so we use an explicit `for` loop.

## Why a final norm?

The stream grows over the layers. We measured this in a real model, the project's SigLIP encoder, with the siglip-base weights:

<Fig caption={<><b>A sign photo (c02) passing through the project's SigLIP.</b> The mean norm per token rises from 5 to 48 over the layers. A single element reaches 213 (the source of the comment in <code>check_encoder.py</code> that "values grow to ~200"). <code>post_layernorm</code> brings everything back to a scale of ≈ √768 · |γ|.</>}>
<SiglipGrowth />
</Fig>

Gemma has the same structure: in the toy model the stream's norm rises from 48 to 57 (<Link to="/gemma/residual">4.2</Link>). lm_head takes a dot product of this stream with the embedding table. Without normalization the scale of the logits would depend on the input and the number of layers.
