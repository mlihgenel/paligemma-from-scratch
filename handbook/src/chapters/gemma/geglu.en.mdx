# The GeGLU MLP

<p className="lead">Two thirds of the model live in this class. Its job is simple: widen each token from 2048 to 16384 and narrow it back, one token at a time. The difference from a classic MLP is that the widening happens along two separate paths, and one of them opens and closes the other like a <b>gate</b>.</p>

## Classic MLP vs gated MLP

The MLP in SigLIP is classic: <span className="mono">fc2(gelu(fc1(x)))</span>. One path: widen, activate, narrow. Gemma's MLP is:

$$
\mathrm{MLP}(x) = W_{\text{down}}\Big(\,\mathrm{GELU}(W_{\text{gate}}\,x) \;\odot\; W_{\text{up}}\,x\,\Big)
$$

There are two parallel widenings. **up** carries "what passes" (linear, no activation). **gate** decides "how much passes" (it goes through GELU). ⊙ is the elementwise product. If the gate is ≈ 0, nothing passes in that dim, whatever up's value is.

<Callout kind="neden" title="Why does the gate work?">
In a classic MLP each intermediate neuron is <span className="mono">gelu(w·x)</span>: the activation of <i>one</i> linear function of the input. In a GLU each intermediate neuron is <span className="mono">gelu(a·x) · (b·x)</span>: the <b>product</b> of two linear functions. A product can directly represent second-order interactions between input features ("if this is present, let that through"). Shazeer's 2020 paper <i>GLU Variants Improve Transformer</i> showed that GLU variants consistently beat the classic MLP at the same budget. Its honest conclusion is fun too: "We offer no explanation as to why these architectures seem to work; we attribute their success, as all else, to divine benevolence."
</Callout>

<Predict q="If the MLP processes each token on its own, is there a difference between feeding a 260-token sequence at once and feeding 260 single tokens?">
Mathematically <b>no</b>. The max difference measured on the toy model is ~1e-6, just noise from the order of float additions. Attention is the only place that carries information between tokens; the MLP transforms information within a token. In practice feeding them together is much faster, because it becomes one big matmul.
</Predict>
