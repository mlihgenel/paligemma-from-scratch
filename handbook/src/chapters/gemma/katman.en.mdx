<Step>The layer takes <S s="B, T, D" /> and returns the same shape. Besides the stream it gets the RoPE table, the mask and an optional KV cache, all for attention only.</Step>
<Step>`residual = hidden_states`: a copy of the stream is set aside **before the norm**. In Python this is not a copy but a second name for the same tensor. The next lines create new tensors, so that is fine.</Step>
<Step>`input_layernorm`: now `hidden_states` is no longer the stream but a **normalized copy**. The stream waits in `residual`.</Step>
<Step>`self_attn`: the branch's computation. This is where tokens see each other (<Link to="/gemma/attention">4.11</Link>). The output has the same shape as the input, so it can be added to the stream.</Step>
<Step>`residual + hidden_states`: the branch output is **added** to the stream. `hidden_states` is the stream again, in its updated form.</Step>
<Step>The same pattern for the MLP block: first the stream goes into `residual` again.</Step>
<Step>`post_attention_layernorm`: despite the name, the norm at the MLP's **input**.</Step>
<Step>`mlp`: GeGLU. Nothing mixes across tokens (<Link to="/gemma/geglu">4.5</Link>).</Step>
<Step>The second addition. The output has the same shape as the input, ready for the next layer.</Step>
</Scrolly>

<Predict q="In how many different 'meanings' is the hidden_states variable used during forward?">
Three: (1) the stream itself (at the input and after every ⊕), (2) a normalized copy of the stream, (3) a branch output (attn or mlp). In Python they all share one name. While reading, asking "what does this variable hold right now?" is the best way to catch bugs. HF uses this style too. Weights are matched by attribute name, not by local variable names, so renaming local variables would be harmless.
</Predict>

## Mixing up the norms

Both norms are the same class with the same shape. Swapping them is a one-word bug. With zero-initialized weights the two norms behave **exactly the same**, so the bug is invisible.

<BreakIt title="swap input_layernorm and post_attention_layernorm"
  good={`hidden_states = self.input_layernorm(hidden_states)          # ← attn input
...
hidden_states = self.post_attention_layernorm(hidden_states)  # ← mlp input`}
  bad={`hidden_states = self.post_attention_layernorm(hidden_states)  # ← wrong
...
hidden_states = self.input_layernorm(hidden_states)          # ← wrong`}
  result={(b) => b ? <NormSwapStats broken={b} /> : <p className="small muted" style={{margin: 0}}>Flip the switch to measure the difference in both cases.</p>} />

That is the reason for these lines in <code>check_gemma.py</code>:

```python
# Randomize the norm weights. Left at zero, both norms behave the same and code that
# swaps input_layernorm and post_attention_layernorm would still pass
hf.input_layernorm.weight.normal_()
hf.post_attention_layernorm.weight.normal_()
```
